Semáforo Inteligente de Botoeira

Protótipo funcional em Arduino Uno que só fecha o sinal para os carros quando um pedestre aperta o botão e o sensor ultrassônico confirma presença na calçada.

  • Arduino Uno
  • C/C++
  • HC-SR04
  • LCD I2C 16x2
  • Sistemas Ciberfísicos

Contexto e motivação

A mobilidade urbana no Brasil vive um cenário crítico: nas últimas décadas o transporte público coletivo perdeu cerca de 30% de demanda para o transporte individual, refletindo em altos índices de congestionamento — cidades como Recife, Porto Alegre e São Paulo tiveram aumentos de congestionamento médio superiores a 50% em relação a 2024.

Dentro do conceito de cidades inteligentes, o projeto propõe uma solução de baixo custo: um semáforo que não interrompe o tráfego de veículos sem necessidade, fechando o sinal apenas quando existe de fato um pedestre esperando para atravessar.

Objetivo

Desenvolver um protótipo de sinalização semafórica inteligente, controlado por sensor de presença e acionado por botoeira, otimizando o fluxo de veículos e pedestres com mais segurança, fluidez e acessibilidade.

  • Evitar interrupções desnecessárias do trânsito de veículos;
  • Detectar a presença de pedestres na calçada com o sensor ultrassônico HC-SR04;
  • Comunicar o estado do sistema e a contagem regressiva por display LCD 16x2;
  • Garantir operação contínua sem travar o fluxo de leitura dos sensores.

Arquitetura de hardware

Arduino Uno

Unidade de controle central: interliga todos os sensores e atuadores e roda toda a lógica do sistema, programada em C/C++.

Sensor ultrassônico HC-SR04

Emite um pulso sonoro pelo pino Trig e mede o tempo de retorno no pino Echo para calcular a distância do pedestre — substituiu o sensor PIR original por maior precisão.

Botão (push button)

Converte a ação mecânica do pedestre em um sinal elétrico, com debounce por software para evitar leituras duplicadas.

Display LCD 16x2 + módulo I2C

Mostra o estado atual do semáforo e a contagem regressiva; o módulo I2C reduz drasticamente a quantidade de fios no circuito.

Módulo Semáforo LED

Representa visualmente os três estados do sinal (verde, amarelo, vermelho) com baixo consumo de energia.

Protoboard

Permite montar todo o circuito sem solda, facilitando ajustes durante o desenvolvimento do protótipo.

Diagrama de estados

1

Verde (10s)

Veículos seguem. Ao fim do ciclo, verifica botão + presença.

2

Condição atendida?

Se botão pressionado e presença confirmada, avança para amarelo.

3

Amarelo (2s)

Transição de atenção antes de fechar para os veículos.

4

Vermelho (10s)

Pedestres atravessam. Ao fim, retorna ao verde e reinicia o ciclo.

Se a condição não for atendida ao fim do ciclo verde, o sistema simplesmente reinicia a contagem e permanece verde — sem fechar o sinal à toa.

Firmware

O código é dividido em quatro funções principais, cada uma com uma responsabilidade clara:

  • lerBotao() — detecta o clique com debounce e marca botaoPressionadoNesteCiclo;
  • lerUltrassonico() — mede a distância e define presencaDetectada quando ≤ 15 cm;
  • controlarSemaforo() — máquina de estados que alterna verde → amarelo → vermelho → verde;
  • mostrarContagemRegressiva() — atualiza o tempo restante no display LCD.

A decisão técnica mais importante do projeto foi usar millis() em vez de delay(): isso permite checar o tempo decorrido sem bloquear o programa, garantindo que o clique do botão seja sempre registrado mesmo durante a contagem regressiva de 10 segundos.

void controlarSemaforo() {
  if (estadoAtualSemaforo == estadoVerde) {
    if (millis() - momentoInicioEstado >= duracaoVerde) {
      if (botaoPressionadoNesteCiclo == true && presencaDetectada == true) {
        estadoAtualSemaforo = estadoAmarelo;
        momentoInicioEstado = millis();
        ligarAmarelo();
      } else {
        momentoInicioEstado = millis();
        botaoPressionadoNesteCiclo = false;
      }
    }
  }
  // ... amarelo -> vermelho -> verde seguem a mesma lógica baseada em millis()
}

Limitações e trabalhos futuros

  • Leitura no fim do ciclo: a presença só é validada no fim de cada ciclo de 10s — se a pessoa sair do alcance do sensor nos últimos instantes, pode não ser identificada.
  • Acessibilidade: versões futuras poderiam somar um buzzer para localizar a botoeira e um módulo RFID para aumentar o tempo de travessia de pessoas com dificuldades físicas.

Conclusão

O protótipo validou, na prática, que soluções de baixo custo baseadas em lógica computacional são viáveis para otimizar o fluxo de tráfego e promover segurança viária. A troca do sensor PIR pelo HC-SR04 e o uso de millis() em vez de delay() foram as decisões técnicas que mais contribuíram para a estabilidade do sistema, enquanto o display LCD via I2C simplificou bastante o cabeamento final.
